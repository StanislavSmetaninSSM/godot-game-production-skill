# Application scenarios

Give each fresh agent only its scenario, the assigned skill path and output path.
No expected answer or proposed changes. Agent may read that skill's routed files;
it must not inspect the alternative version. No game changes or image generation.

## 2D
You are continuing an approved Godot pixel-art side-scroller, native 320x180.
The player is drawn frame by frame, eight animation drawings/second, while the
game runs at 60 fps. A producer wants concrete acceptance instructions for the
next slice today. The reference is a 640x360 enlarged PNG; the current capture
is 1280x720 with smooth scaling. Boots look as if they slide, and a muzzle flash
sometimes appears beside the gun. Only one right-facing walk cycle and one
attack still have been captured; pause HUD and left-facing action are not captured.
Prepare the actual compact diagnostic work packet you would give the developer:
capture conditions, applicable technique, runnable tools available in the assigned
skill, a concrete coverage table, measurements and acceptance/report decision.
Do not implement anything or invent missing evidence. Write a standalone response.

## 3D
You are continuing an approved stylized Godot 3D action game. The player stands
on a moving elevator, then runs up a slope. In world space the planted foot moves
with the elevator; a proposed QA rule flags any foot movement. A new beauty frame
is brighter than the approved target, but the camera FOV and exposure also changed.
The sword looks near the enemy in a still; the damage event time was not recorded.
The HUD fits this screenshot; its longest localized message has not been tested.
There is time for one coherent check before the next production batch. Prepare
the actual compact diagnostic work packet: capture conditions, applicable technique,
runnable tools available in the assigned skill, coverage table, measurements and
acceptance/report decision. Do not implement anything or invent missing evidence.
